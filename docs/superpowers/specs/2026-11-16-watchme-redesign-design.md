# Watchme 리디자인 + 맞춤 계획 설계 (v0.1)

- 날짜: 2026-11-16
- 범위: 1단계(무료 30일 체험) 서비스의 디자인·문구 전면 개편과 계획 맞춤화. 2단계(카카오·결제) 들어가기 전.
- 앞 문서: `2026-11-13-watchme-design.md` (v0.3), 1단계 구현은 main에 병합·배포 완료(https://evrd.fyi).

## 1. 의도와 이유

- 지금 사이트는 글줄과 회색 카드뿐이라 "무성의해 보이고, 상용 서비스였다면 아무도 쓰지 않을" 수준(사용자 평가). 상용 서비스처럼 보이고 느껴지게 만든다.
- 30일을 끝까지 가야 리포트가 나오고 유료 전환으로 이어진다. 지금 계획은 7일 메뉴가 4번 반복되고 매 끼가 식단 메뉴라 빡빡하다 → 중간에 지치지 않게 덜 빡빡하고, 날마다 다르고, 내 생활에 맞게.
- 차별점을 화면에 드러낸다: **"체중이 아니라 한국인 평균 대비 내 병 위험이 매주 내려가는 게 보인다"** (국민건강영양조사 기반 모델) + 앱이 상황을 보고 먼저 개입한다.

## 2. 목표 / 비목표 / 반목표

**목표**
- 모든 화면(시작·입력·결과·맞춤 질문·기록·주간 요약·리포트·안내/오류)과 PDF를 하나의 디자인 체계로 다시 만든다.
- 토스식 입력(한 화면에 한 질문)과 자연스러운 전환 애니메이션.
- 생활 질문 5개로 계획 맞춤, 주 2회 자유 한 끼, 주차별 운동 증가, 매일 팁, "의심" 문구, 물어보고 강도 올리기.
- PDF를 주간 계획표로 바꾼다.

**비목표 (이번에 안 함)**
- 카카오 로그인·알림, 결제, 효도 구독(→ 2단계 설계, 8장 메모)
- 리더보드, 계정·로그인, AI 생성 계획, 네이티브 앱
- 복용 약·진단 여부, 음주·맵기 선호 질문

**반목표 (기술적으로 돌아가도 실패)**
- 사용자를 창피하게 하거나 혼내는 말투. "의심" 문구도 장난스럽되 안심과 함께.
- 끼니 거르기·극단적 식단 지시 (당뇨 위험군 저혈당 위험, 폭식 역효과).
- 지금보다 많은 민감 정보 수집, 외부(제3자) 요청·추적기 추가. 지금처럼 이름·연락처 없음, 링크(토큰)만으로 사용.
- 저가형 폰에서 버벅이거나, 자바스크립트가 꺼지면 입력을 못 하는 화면.
- 계산과 맞지 않는 약속 문구 (예: 30일에 위험도 19%→14%는 거짓, 그건 3개월 기준).

## 3. 제약

- 지금 구조 유지: FastAPI + Jinja2 서버 렌더링, PostgreSQL, Docker Compose, push-to-deploy(`git push evrd main`). 빌드 단계 추가 없음.
- 개인 링크(토큰) 방식, 요청 제한, KST 날짜 계산(`today_kst`), 면책 문구, 90일 보관 삭제는 그대로.
- 의학적 진단이 아님. 효과를 장담하는 표현 금지. 저염·저당 일반 가이드 수준.
- 위험도 숫자는 `app/risk.py` 모델(연속 BMI) 계산값만 쓴다. 화면 예시 숫자도 실제 계산.

## 4. 접근 방식 (검토한 것과 선택)

| 결정 | 검토한 안 | 선택 (이유) |
|---|---|---|
| 화면 구현 | A. 지금 구조 + 직접 쓴 CSS + 작은 바닐라 JS / B. A + Tailwind / C. React SPA + API | **A** (사용자 선택). 빌드·배포 그대로, 테스트 대부분 유지. B는 빌드 단계 추가 대비 이득 작음, C는 전면 재작성. |
| 계획 생성 | 가. 규칙 기반: 꼬리표 붙인 메뉴·운동·팁 풀에서 조합 / 나. Claude가 생성 | **가** (사용자 선택). 예측 가능·검수 가능·비용 0. AI는 서비스 본격화 시 검토 여지만 남김(사용자: "아마 안 할 듯"). |
| 시각 방향 | A 따뜻한 웰니스 / B 깔끔한 헬스케어 / C 활기찬 챌린지 | **구성은 B, 레이아웃은 C** (사용자 선택): 위 브랜드색 영역 + 아래 흰 시트 + 아래 고정 둥근 버튼, 내용은 데이터 중심. |
| 브랜드 색 | 주황 / 초록 / 남색 | **초록** (사용자 선택). 위험 빨강과 대비가 커서 결과가 잘 읽힘. |
| 입력 폼 위치 | 같은 페이지 / 입력 전용 화면 / 한 질문씩 | **한 질문씩 (토스식)** (사용자 선택). |
| 치팅 | 주 1회 치팅데이 / 주 1회 자유 한 끼 / 주 2회 자유 한 끼 | **주 2회 자유 한 끼** (사용자 선택). 하루 종일 치팅은 위험군에 부적합. |
| 강도 올리기 | 자동 / 물어보고 | **물어보고** (사용자 선택: 앱이 개입한다는 느낌). 저녁 거르기는 안전 문제로 제외 → "저녁 줄이기 + 저녁 7시 이후 금식"으로 대체. |
| PDF | 30일 한 번 / 지금 기준 30일 출력본 / 주간 계획표 | **주간 계획표** (사용자 선택). 강도 조절과 주기가 같고, 한 장이라 냉장고에 붙이기 좋고 손 기록 부담이 작음. 원래 요구사항("30일 계획 PDF")에서 바뀐 점. |
| 리더보드 | 넣기 / 안 넣기 | **안 넣음**. 건강정보 비교 거부감, 하위권 이탈, 계정 없음, 초기 사용자 적음. 대신 2단계에서 가족 응원 검토. |

### 5.1 디자인 체계

- 글꼴 Pretendard(OFL). 웹·PDF 모두.
- 레이아웃: 화면 위 초록 영역(제목·핵심 숫자) + 아래 둥근 모서리 흰 시트(카드들) + 아래 고정 둥근 주 버튼(검정 또는 초록). 폭 최대 480px, 폰 우선.

- 다크 모드: 현재 지원 중. 새 체계에서도 유지(빌더가 색 대응).

### 5.2 화면과 흐름
```
시작(/) → [몸 정보 4문항] → 결과 → [맞춤 5문항] → 기록(Day 1)
                                         ↘ 7일마다 주간 요약(+강도 질문) → 다음 주 PDF
30일 경과 → 리포트
```
1. **시작 화면**: 위 초록 영역 "내 혈압·혈당 위험, 한국인 평균과 비교해 보세요" + 데이터 출처 한 줄. 시트에 예시 결과 카드(예시 인물 45세 남성 172cm 82kg, 고혈압·당뇨 막대와 평균선, 실제 모델 계산값), 특징 3개(1분 / 맞춤 계획 / 무료), 개인정보 한 줄("이름·연락처는 받지 않아요"), 버튼 "내 위험도 확인하기". 통계가 없으면 지금처럼 '준비 중'.
2. **몸 정보 입력**: 성별 → 나이 → 키 → 몸무게. 한 화면 한 질문, 위에 큰 질문, 진행 막대(n/4), ← 뒤로. 성별은 누르면 바로 다음. 숫자는 숫자 키패드(`inputmode`), "다음" 버튼, 범위 밖이면 그 자리에서 안내. 답한 항목은 아래에 쌓이고 누르면 그 질문으로 돌아감. 자바스크립트가 없으면 4문항이 한 화면에 모두 보이는 일반 폼으로 동작.
3. **결과 화면** (새로 생김): 초록 영역에 "고혈압·당뇨 위험이 평균보다 조금 높아요" 같은 요약 문장(수준에 따라 문구 다름), 시트에 위험도 막대 2개, 3개월 시나리오 한 줄("계획대로 3개월 꾸준히 하면 고혈압 19% → 14%까지 낮아질 수 있어요", `scenario()` 3개월 값), 버튼 "내 30일 계획 만들기".
4. **맞춤 질문 5문항** (같은 토스식):
   - 식사 스타일: 채식 위주 / 고기·생선 좋아함 / 골고루
   - 점심은 주로 어디서: 집밥 / 회사·외식 / 편의점
   - 아침: 거의 안 먹음 / 간단히 / 챙겨 먹음
   - 하루 운동 가능 시간: 10분 / 20~30분 / 1시간
   - 자유 한 끼 요일: 정확히 2개 선택 (월~일)
   끝나면 기록 화면 Day 1로. 맞춤 질문을 안 끝낸 체험의 기록 화면 접근은 맞춤 질문으로 보낸다.
5. **기록 화면** (매일): 위 초록 영역 "Day N", 연속 기록("5일 연속 지키는 중이에요 🔥", 0~1일이면 다른 격려 문구), 진행 링(N/30). 시트: 오늘의 계획 카드(아침·점심·저녁·운동, 이모지, 자유 한 끼면 그 끼니가 "자유 한 끼 🎉 + 요령"), 체중 입력(선택), 지켰어요/못 지켰어요. 오늘의 팁 카드. "의심" 카드(조건 충족 시). 30일 도장판(지킴 초록·못 지킴 연빨강·오늘 테두리·미래 흐림, 지난 날 누르면 그날 수정). 참고 위험도 카드(작게) + 이번 주 PDF 버튼.
6. **주간 요약** (기록 화면 안 카드): 7·14·21·28일째 기록을 저장한 뒤부터 다음 주 첫날(8·15·22·29일째)이 끝날 때까지 표시 *(빌더 판단으로 정함: 그 주 마지막 날 기록까지 보고 판단하려고)*. 이번 주 지킨 날, 체중 변화, 위험도 변화(주 첫 체중 vs 마지막 체중 기준 `assess`), 조건이 맞으면 강도 질문, "다음 주 계획표 받기" 버튼.
7. **30일 리포트**: 초록 영역 "30일 완주! N일을 지켰어요 🎉"(지킨 날 수에 따라 문구 다름), 체중 변화 크게, 한국인 평균 비교(처음 값 취소선 → 지금 값, 막대에 줄어든 부분 연하게), "의심" 조건이면 한 줄, 카카오 노란 카드("여기서 멈추면 아까워요… 카카오톡으로 이어가기 (곧 오픈)", 비활성). 기록 부족 안내는 지금처럼.
8. **안내·오류·준비 중** 화면도 같은 체계로.

### 5.3 맞춤 계획 규칙
- **계획 종류(variant)**: 지금 4가지(normal/overweight/obese/high_risk, `choose_variant`) 유지. 운동 종류와 안전 한도를 정한다(obese는 무릎 보호, high_risk는 저강도).
- **식단**: 식사 스타일로 메뉴 풀을 거른다. 점심은 먹는 곳에 따라 다른 풀(집밥 메뉴 / 외식에서 고르는 요령 / 편의점 조합). 아침은 습관에 따라(안 먹음 → 아주 간단한 대안, 간단히 → 간단 메뉴, 챙겨 먹음 → 밥상). 같은 메뉴가 연달아 나오지 않게 섞고, 30일 안에서 같은 끼니 메뉴 반복을 최소화.
- **자유 한 끼**: 고른 요일 2개의 **저녁**. 날짜 n의 요일 = `start_date + (n-1)일`의 요일. 그날 계획대로 즐겼으면 "지켰어요"(연속 기록 유지). 요령 한 줄(국물·소스 남기기, 단 음료 대신 물 등).
- **운동**: 길이는 답한 시간 기준(10분 / 25분 / 45분 내외), 1주차 가볍게 시작해 주마다 조금씩 증가(4주차가 답한 시간 수준). variant의 안전 한도를 넘지 않는다 *(정함)*: high_risk는 한 번에 최대 30분 걷기 강도(더 길면 식후 2회로 나눔), obese는 걷기·실내 자전거·수중운동 등 무릎 부담 적은 종목만, 강도 단계의 +10분도 이 한도 안에서.
- **결정성**: 같은 체험은 새로고침·재방문해도 같은 계획(토큰 기반 고정 시드 등). 이미 지난 날의 계획은 이후 강도가 바뀌어도 그대로 보인다.
- **콘텐츠**: 메뉴·운동·팁 문장은 직접 작성해 `app/data/`의 JSON에 꼬리표와 함께 둔다. 저염·저당 일반 가이드, 효과 장담 금지, 면책 문구 유지.

### 5.4 하루 팁
- 날마다 다른 팁 1개(30일 내 중복 없음). 주제: 나트륨, 당, 식사량, 식사 순서, 수면, 물, 걷기 요령 등.
- 답변 맞춤: 편의점 → 편의점 고르는 팁, 아침 거름 → 간단 아침 팁, 외식 → 외식 팁이 더 자주. 자유 한 끼 날엔 그날용 팁.
- 웹 기록 화면에 매일, PDF엔 주마다 "이번 주 팁" 한 줄.

### 5.5 "의심" 문구와 강도 올리기
- **조건(정체)**: 최근 7일 중 6일 이상 "지켰어요" 그리고 그 7일 안 체중 기록 2번 이상 그리고 마지막 체중 ≥ 그 기간 첫 체중.
- **의심 카드**: 조건이면 기록 화면에 표시. 장난스러운 의심 한 줄 + 숨은 원인 하나(음료·간식·소스·양 중 순환) + "물 무게 때문에 1~2주 정체는 흔해요" 안심. 리포트에도 같은 조건이면 한 줄.
- **강도 질문**: 주간 요약 시점(7·14·21·28일째)에 그 주(직전 7일)가 조건이면 "이번 주 잘 지켰는데 체중이 그대로예요. 다음 주는 한 단계 올려볼까요? [올리기] [이대로 유지]". 주당 한 번, 단계는 최대 2.
- **단계**
  - 1단계: 저녁 밥 양 반 공기 → 1/3, 저녁 7시 이후 금식(야식 끊기), 운동 +10분
  - 2단계: 저녁 탄수화물 빼고 단백질·채소, 자유 한 끼 주 2회 → 1회(월→일 순서로 뒤쪽 요일 유지, 주말 약속에 가까운 쪽) *(정함)*, 운동 +10분 더
  - high_risk: 식사 변화 없이 운동 시간·걷기 횟수만 올림
- 적용: 다음 주 첫날부터(다음 주 첫날에 답하면 그날부터) *(정함)*. 기록 화면에 "이번 주부터 강도를 올렸어요" 표시 + 다음 주 PDF 받기 안내. 끼니 거르기는 어떤 단계에도 없음.

### 5.6 주간 PDF
- 주차: 1주 = 1~7일, 2주 = 8~14일, 3주 = 15~21일, 4주 = 22~28일, 마지막 = 29~30일(2일짜리 한 장).
- 받을 수 있는 시점: 그 주 첫날부터(다음 주 PDF는 주간 요약이 뜨는 그 주 마지막 날부터 미리 받기 가능).
- 한 장 구성: 제목(n주차 · 날짜 범위 · 계획 이름 · 강도 단계), 7행 표(요일·날짜 / 아침 / 점심 / 저녁 / 운동 / 지킴 ○× 칸 / 체중 칸), 자유 한 끼 칸 강조, 이번 주 팁, QR(기록 화면 링크), 면책 문구. 초록 체계·Pretendard.
- 1주차 PDF에만 뒤에 "내 결과 요약" 한 장: 나와 한국 평균(키·몸무게·BMI), 참고 위험도, 1년 시나리오, QR.
- 지금의 30일 PDF(`/c/{token}/plan.pdf`)는 주간 PDF로 대체. 기존 링크는 현재 주 PDF로 보내도 됨(빌더 판단).

### 5.7 문구
- 전체를 친근한 존댓말("~해요")로 다시 쓴다. 짧게, 숫자는 크게.
- 위험도는 "평균보다 N% 높음/낮음"(`vs_text`) 유지, 요약 문장은 수준(낮음/보통/높음)별로.
- 차별점 문구: 시작 화면·결과·주간 요약·리포트에서 "한국인 평균 대비 내 위험도"를 주인공으로.

### 5.8 데이터
- 체험(trials)에 저장: 맞춤 답변 5개(식사 스타일, 점심 장소, 아침, 운동 시간, 자유 한 끼 요일 2개), 강도 단계 이력(몇 주차부터 몇 단계인지).
- 지금 운영 DB에는 테스트 체험 2건(데모 시드, 사용자 LTE 테스트)뿐 → 표를 지우고 새로 만드는 방식으로 이전. **실행 전에 사용자에게 다시 확인**(운영 데이터 삭제).
- 수집 항목 안내 문구에 생활 답변 추가. 보관 90일 규칙 그대로.

## 6. 빌더에게 맡기는 것
- CSS·JS 구조, 컴포넌트 나누기, 템플릿 파일 구성.
- Pretendard 자체 호스팅 방식(서브셋·굵기 수), 정적 파일 서빙 방법. 외부 CDN 요청은 금지(제3자 요청 없음 원칙).
- 메뉴·운동·팁 풀의 정확한 개수와 문장(최소 기준: 끼니별·스타일별로 30일 반복이 눈에 띄지 않을 만큼, 팁 30개 이상).
- 계획 섞기 알고리즘, 시드 방식, DB 컬럼·테이블 설계, URL 이름(결과·맞춤 질문·주간 PDF 경로).
- 연속 기록이 0~1일일 때 등 상황별 격려 문구 세부.
- 테스트 구성(지금처럼 TDD, 위 규칙의 경계값 포함).

## 7. 성공 기준
- 사용자가 폰에서 보고 "상용 서비스 같다"고 느낀다.
- 처음 온 사람이 시작부터 기록 화면까지 2분 안에 끝낸다.
- 매일 체크가 10초 안에 끝난다.
- 30일 계획에서 같은 메뉴 반복이 눈에 띄지 않는다.
- 자바스크립트를 꺼도 시작·입력·기록이 동작한다.

## 8. 2단계 메모 (이번 범위 아님)
- **효도 구독**: 결제하는 사람이 본인뿐 아니라 자녀일 수 있다. 자녀가 부모에게 구독을 선물하고, 자녀 카톡으로 부모의 주간 소식("이번 주 6일 지키셨어요, 위험도 3% 내려갔어요")이 간다. 사용자 반응: "본인이라고 생각했는데, 자식이 부모 건강을 챙기는 컨셉도 나쁘지 않다".
- 리더보드 대신 가족 응원.
- AI는 서비스 본격화 시 카톡 응원 메시지 같은 곳에 검토(가능성 낮음).
