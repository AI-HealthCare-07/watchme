# Watchme 3단계 설계: AI 한 줄 요청 (2026-11-18)

## 1. 왜 하나
- 사용자 목표: 무료 LLM API를 하나 붙여 "AI를 썼다"고 말할 수 있을 만큼만 개인화한다. AI 사용은 최소로.
- 효도 구독·결제는 사업자 정리 전이라 보류. 서비스는 당분간 무료.
- 지금 계획은 규칙(위험도 계열, 설문 5개, 자유 한 끼, 강도)과 미리 쓴 문장 조합이다. 설문 선택지로 못 담는 개인 사정("매운 거 못 먹어요", "무릎이 안 좋아요")을 한 줄로 받아 반영한다.

## 2. 목표 / 비목표 / 안티 목표
**목표**
- 설정 마지막에 선택 입력 "한 줄 요청"을 받는다.
- AI(Gemini 무료 요금제)는 **이 체험의 후보 메뉴·운동 목록에서 뺄 것만 고르고**, 이유를 한 줄로 쓴다. 체험당 호출 1번.
- 준비 화면에 "🤖 AI가 요청을 반영했어요" + 이유 한 줄. 기록 화면 제목 밑 칩에 "🤖 AI 맞춤".
- 키가 없거나 AI가 실패해도 지금과 똑같이 동작한다.

**비목표 (이번에 안 함)**
- B. 주간 요약 "AI 코치 한마디" → **나중에 할 일**. 같은 클라이언트(`app/ai.py`)를 재사용해 주 1회 호출로 붙이면 된다.
- AI가 새 메뉴·운동을 만들기, 30일 계획 통째로 짜기, 시작 화면 트리아지를 AI로 쓰기.
- 설정 후 요청 고치기(다시 하려면 새 체험).
- 효도 구독, 결제.

**안티 목표 (이렇게 되면 실패)**
- AI 문장이 진단·처방처럼 읽힌다.
- 체중·위험도·나이 같은 건강 정보가 AI로 나간다.
- AI가 막혀서 설정이 실패하거나 계획이 비거나 모자란다.

## 4. 동작
### 4.1 설정 화면
- 생활 질문 5개 뒤에 6번째 단계(선택): "식단·운동에서 빼고 싶은 게 있나요?"
  - `<textarea name="ai_request" maxlength="100">`, placeholder "예: 매운 거 못 먹어요, 무릎이 안 좋아요".
  - 안내(입력 칸 바로 아래): "적은 내용은 AI(구글 Gemini)로 보내져요. 이름·연락처는 적지 마세요."
  - 비워도 된다. 비우면 AI를 부르지 않는다.
- `ai.enabled()`가 거짓(키 없음)이면 이 단계 자체를 그리지 않고, 폼에 값이 와도 무시한다.
- JS 없이도 동작(기존 단계 폼 규칙 그대로).

### 4.2 AI 호출 (설정 POST 안에서, 동기)
- 설정 저장이 끝난 뒤, 요청이 비어 있지 않으면 1번 호출. 타임아웃 8초, 재시도 없음.
- **보내는 것**: 한 줄 요청(앞뒤 공백 제거, 100자 자르기) + 이 체험의 후보 목록뿐.
  - 후보 = 프로필로 거른 아침·점심·저녁 메뉴 풀 + 계열(variant) 운동 목록. 각 항목에 짧은 번호(`b1`, `l3`, `d7`, `e2`)를 붙여 보낸다. 운동 문장의 `{m}`은 `N`으로 바꿔 보낸다.
  - 성별·나이·키·체중·위험도·토큰은 **보내지 않는다**.
- **받는 것**(JSON 모양 지정): `{"exclude": ["b1", ...], "reason": "..."}`.
- 시스템 지시(요지): 요청에 맞지 않는 항목 번호만 고른다. 목록에 없는 번호를 만들지 않는다. 이유는 한국어 한 문장 60자 이내, 무엇을 뺐는지만 말한다. 진단·처방·효과 약속을 하지 않는다. 요청이 식단·운동과 무관하면 빈 목록과 빈 이유.
- **검증** (하나라도 어기면 AI 결과 전체를 버림):
  - JSON 파싱 실패, 모양 불일치.
  - 목록에 없는 번호(그 번호만 버리지 않고 전체 버림. 엉뚱한 답의 신호).
  - 종류별(아침·점심·저녁·운동)로 빼고 남은 개수가 원래의 절반(올림)보다 적음.
- `reason`은 공백 정리 후 80자로 자른다. 비어 있으면 "요청에 맞춰 일부 메뉴를 뺐어요".
- 빼는 항목이 0개면 저장은 하되 화면엔 "요청을 확인했어요. 지금 계획에서 뺄 게 없었어요"로 보여 준다.

### 4.3 저장
- 새 표 `ai_picks` (기존 표는 안 바꿈, `create_all`로 생성):
  - `token` PK, FK → trials CASCADE
  - `request` Text (사용자가 쓴 한 줄)
  - `excluded` Text: 뺀 항목의 **원문 문장** 목록(JSON 배열). 인덱스가 아니라 문장으로 저장 → `meals.json`/`exercises.json` 순서가 바뀌어도 안전. 나중에 문장이 바뀌면 그 항목은 그냥 안 빠짐.
  - `reason` Text
  - `status` String(8): `ok` | `empty`(뺄 것 없음) | `failed`(호출 실패·검증 실패)
  - `created_at`
- `failed`도 남긴다(화면 안내와 운영 확인용). 실패 이유 상세는 저장하지 않고 서버 로그에 종류만(timeout / http / invalid) 남긴다. 요청 문장은 로그에 쓰지 않는다.
- `purge_expired`가 체험과 함께 `ai_picks`도 지운다(다른 표처럼 명시적 delete).
- `next_trial`(다음 30일 도전)은 `ai_picks` 행을 그대로 복사한다. AI를 다시 부르지 않는다.

### 4.4 계획에 반영
- `build_plan(profile, start_date, seed, decisions, exclude=frozenset())`: 풀을 섞기 전에 `exclude` 문장을 뺀다. 운동은 `{m}` 들어간 원문 기준으로 비교.
- 계획을 만드는 모든 곳이 같은 제외 목록을 써야 한다: 기록 화면, 주차 PDF, 아침 카톡 메시지(`notify`), 준비 화면 등 `build_plan` 호출부 전부. 호출부가 직접 `ai_picks`를 읽지 않도록 서비스에 한 군데(예: `plan_for(db, trial)`)를 둔다.
- `status != ok`면 제외 없음 = 지금과 같은 계획.

### 4.5 화면
- 준비 화면(`/c/{token}/ready`), `ai_picks`가 있을 때만:
  - `ok`: "🤖 이 계획은 AI가 내 요청에 맞춰 골라 줬어요" 한 줄. 뺀 항목·`reason`은 보여 주지 않음(2026-11-18 사용자 피드백, `reason`은 저장만).
  - `empty`: "요청을 확인했어요. 지금 계획에서 뺄 게 없었어요."
  - `failed`: "지금은 AI 요청을 반영하지 못했어요. 기본 계획으로 시작해요."
- 기록 화면: `status == ok`이면 제목 밑 칩 줄에 "🤖 AI 맞춤" 칩 하나. 그 외 문구 없음.
- 개인정보 안내(`privacy()`)에 한 문장 추가: "한 줄 요청을 적으면 그 내용은 AI(구글 Gemini)로 보내고, 체험과 함께 지워요."

## 5. 설정·운영
- 서버 `.env`에 `GEMINI_API_KEY` (사용자가 직접 입력, 값은 보지도 다루지도 않음). `compose.yaml`에 전달, `.env.example`에 이름만.
- `GEMINI_MODEL` 환경변수(기본값은 구현 시점의 무료 Flash 모델 이름, 구현 때 공식 문서로 확인). 모델 이름이 자주 바뀌어서 둔 손잡이.
- `ai.enabled()` = `GEMINI_API_KEY`가 있음.
- 호출은 기존 의존성 `httpx`로 REST 직접 호출(새 라이브러리 없음). 테스트는 `kakao.http`처럼 모듈 변수 `ai.http`를 `httpx.MockTransport`로 바꿔 끼운다.
- 남용: 호출은 설정 POST에서만, 체험당 1번(설정은 한 번만 가능). 체험 생성은 기존 IP 제한이 막는다. 무료 한도를 넘으면 429 → `failed` → 기본 계획.
- 키: 다른 프로젝트 키를 같이 쓰지 말고 이 앱용 키를 따로 만든다(사용자 판단 사항, 6장).
- runbook에 13장(AI) 추가: 키 발급 위치, `.env`, 재시작, 첫 실험 기록.

## 6. 사용자에게 남은 결정
- API 키를 다른 프로젝트(ssot-ai-demo)와 같이 쓸지: 권장은 따로 만들기. 같은 구글 프로젝트 안에서 키만 따로 만들면 끊기·교체는 따로 되지만 무료 한도는 공유한다. 한도까지 나누려면 구글 프로젝트도 따로.

## 7. 빌더 재량
- 설정 화면 6단계의 정확한 레이아웃·버튼 문구("건너뛰기" 등), 준비 화면 카드 모양(기존 `.note`/카드 체계 안에서).
- 프롬프트 문장 다듬기(4.2 요지는 지킬 것).
- `excluded` 직렬화 방식(JSON 배열 권장).

## 8. 성공 기준
- "매운 거 못 먹어요"를 적으면 30일 계획에서 매운 메뉴가 빠지고, 준비 화면에 이유 한 줄이 보인다.
- 키를 지우면 6단계가 사라지고 1·2단계 흐름이 그대로 동작한다.
- AI가 엉뚱한 번호를 주거나 다 빼라고 해도 계획은 기본 계획으로 정상 생성된다.
- AI로 나가는 요청 본문에 체중·나이·위험도·토큰이 없다(테스트로 확인).
