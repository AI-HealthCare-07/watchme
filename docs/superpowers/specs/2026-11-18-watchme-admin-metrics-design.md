# Watchme 운영 지표 페이지 설계 (짧은 설계)

2026-11-18 · 사용자와 대화로 정함 · 구현 완료(브랜치 `admin-metrics`)

## 왜
- 첫 목표는 **실제로 쓰는 사람을 늘리는 것**, 특히 **카톡 연결자**다. 포트폴리오와 12월 발표에서 "실제 사용자"를 숫자로 보여 줘야 한다.
- 우선순위: 발표용 숫자가 먼저, 매일 운영 확인이 그다음.
- 랜딩 개선에 쓰려고 "랜딩을 본 사람 중 몇 %가 시작했나"를 알고 싶다.

## 목표 / 하지 않을 것 / 실패로 볼 것
- **목표**
  - 나만 여는 `/admin` 한 화면.
  - 맨 위에 카톡 연결자 수를 크게 보여 준다.
  - 그 아래 날짜별 추이, 단계별 전환, 체크 지속률, 카톡 발송·실패(A-3)를 보여 준다.
  - 날짜별 랜딩 조회수 카운터를 둔다.
- **하지 않음**
  - 매일 아침 요약 카톡(사용자 결정).
  - 외부 분석 도구.
  - 개인별 목록이나 개인 상세.
  - 광고성 메시지 기능. 지금 받은 동의(계획 알림)로는 보낼 수 없다. 하려면 카카오톡 채널 추가 동의를 받는 별도 작업이 필요하다.
- **실패로 볼 것**
  - 비밀값 없이 페이지가 열리는 것.
  - 카운터가 사람을 식별하는 정보(IP·쿠키 ID·토큰)를 남기는 것.
  - 내 테스트 체험이 숫자를 부풀리는 것.

## 고른 방향
| 안 | 결과 |
|---|---|
| **관리 페이지 + 방문 카운터** | **채택** |
| + 매일 요약 카톡 | 안 함 (페이지 즐겨찾기로 충분) |
| 외부 분석 도구 | 안 함 (개인정보·가벼움) |

## 화면 (위→아래)
1. **💬 카톡 연결자 (큰 숫자)**
   - "지금 알림 받는 사람" = `can_message` 이고 `notify` 이고 토큰이 있는 계정.
   - 옆에 작게: 전체 연결 계정, 끊김(토큰 없음/동의 없음), 알림 끔, 오늘 새 연결.
2. **최근 30일 날짜별 표**
   - 칸: 랜딩 조회 · 시작 · 질문 완료 · 새 카톡 연결 · 체크한 사람 수.
   - 숫자 옆에 CSS 막대를 그린다. 라이브러리는 쓰지 않는다.
3. **단계별 전환 (기간 전체)**
   - 랜딩 조회 → 시작 → 질문 완료 → 카톡 연결.
   - 각 단계 수와 앞 단계 대비 %.
   - 조회수는 중복 포함이라 "참고"로 표시한다.
4. **체크 지속률**
   - 1·7·14·30일째에 도달한 체험 중 그날 이후에도 기록이 있는 비율.
   - 함께 "30일 완주 후 다음 도전" 수.
5. **AI 한 줄 요청**: 사용 수, ok / empty / failed.
6. **카톡 발송 최근 7일**: 날짜 × 아침/저녁 보냄·실패 (A-3).
7. 맨 아래 기준 안내: "테스트 제외 기준 · 조회수는 중복 포함 · 90일 지난 체험은 자동 삭제되어 빠짐".

## 정한 것
- **들어가는 방법**
  - 서버 `.env`의 `ADMIN_KEY`를 쓴다. 값은 사용자가 직접 정해 넣는다. Claude는 보지 않는다.
  - `ADMIN_KEY`가 없으면 `/admin`은 404(기능 꺼짐).
  - `/admin?key=…`가 맞으면 HttpOnly 쿠키를 굽고 `/admin`으로 다시 보낸다. 주소창·방문 기록에 키가 남지 않게 하려는 것이다. 쿠키 값은 키 자체가 아니라 키의 해시다.
  - 틀린 키는 기존 `AUTH_PER_IP` 제한을 쓴다.
  - 응답에 `noindex`, `no-store`를 붙인다.
- **방문 카운터**
  - 새 표 `landing_views(day, count)`.
  - 랜딩(`GET /`)을 열 때 KST 날짜 행에 +1 한다.
  - 봇·링크 미리보기(User-Agent에 bot / crawl / spider / kakaotalk-scrap / facebookexternalhit / preview 등)는 세지 않는다.
  - IP·쿠키·User-Agent는 저장하지 않는다.
- **발송 기록 (A-3)**
  - 새 표 `send_runs(day, kind, sent, failed)`.
  - `scripts/send.py`가 실행마다 `send_all`의 (보냄, 실패)를 더해 기록한다.
  - 계정 정보는 남기지 않는다.
- **테스트 제외**
  - (1) `.env`의 `METRICS_SINCE=YYYY-MM-DD`(선택)보다 먼저 만든 체험·계정은 뺀다.
  - (2) 관리자 쿠키가 있는 브라우저로 시작한 체험은 새 표 `test_trials(token)`에 적어 두고 뺀다. 체험이 지워지면 함께 지운다.
- **DB 변경**: 새 표 3개뿐이다. 서버가 켜질 때 `create_all`로 자동으로 생기므로, 기존 표를 바꾸거나 지울 일은 없다.

## 사용자 몫
- 서버 `.env`에 `ADMIN_KEY`(길고 무작위인 값)를 넣는다. `METRICS_SINCE`는 선택이다.
- 배포 후 휴대폰·PC에서 `https://evrd.fyi/admin?key=…`로 한 번 들어가 즐겨찾기한다.

## 만드는 사람에게 남긴 것
- 집계는 열 때마다 SQL로 한다. 사용자가 많지 않으니 캐시는 두지 않는다.
- 화면은 기존 카드 스타일을 쓴다.
- 발표 캡처를 생각해 휴대폰 폭에서도 표가 넘치지 않게 한다(필요하면 가로 스크롤 상자).
