# 카톡 알림 시간 선택 — 설계 (짧은 버전)

## 왜
아침 7:30·저녁 9시 고정이라 생활 시간이 다른 사람(일찍 출근, 교대 근무, 늦은 퇴근)에게는 메시지가 맞지 않는다. 카톡을 연결한 사람이 아침·저녁 시간을 직접 고르게 한다. 발표 자료 "다음 단계"의 첫 항목이기도 하다.

## 목표 / 하지 않을 것
- 목표: 아침 메시지(오늘 계획·주간 리포트·완주 리포트)와 저녁 메시지(기록 확인) 시간을 각각 30분 단위로 고른다.
- 하지 않을 것: 요일별 다른 시간, 아침만·저녁만 끄기, 폰 푸시 알림, 카톡 채널.
- 실패로 볼 것: 같은 메시지가 하루 두 번 가거나, 시간을 바꾼 날 엉뚱한 시각에 메시지가 가는 것.

## 정한 것 (사용자 결정)
- 고르는 방식: 30분 단위 목록. 아침 05:00~10:30, 저녁 18:00~23:30 (각 12칸). 기본값 07:30 / 21:00.
- 발송 방식: cron을 30분마다(매시 0분·30분) 실행하고, 그 칸이 내 시간인 사람에게만 보낸다. 밀린 메시지는 따라잡지 않는다(서버가 그 칸에 꺼져 있었으면 그날은 놓침 — 지금과 같음).

검토했지만 고르지 않은 방법:
- 밀린 메시지 따라잡기: 시간을 바꾼 날 오후에 아침 계획이 가는 문제가 생겨 규칙이 늘어난다.
- 앱 안 스케줄러: 새 의존성, 재시작 때 놓치거나 겹칠 수 있음. cron보다 나은 점 없음.

## 설계 (내 판단, 고칠 수 있음)
- 저장: `kakao_accounts`에 `morning_at`, `evening_at`(시각, 기본 07:30·21:00) 두 칸 추가. 표 개수는 11개 그대로.
  - 이 프로젝트는 마이그레이션 도구 없이 `create_all`만 쓰므로, 운영 DB에는 배포 전에 `ALTER TABLE kakao_accounts ADD COLUMN ... DEFAULT ...` 두 줄을 직접 실행한다(기본값이 있어 기존 코드에 영향 없음). runbook에 기록.
- 발송: `scripts/send.py`는 인자 없이 실행하면 지금 KST 시각을 30분 칸으로 내림해서, 아침 시간이 그 칸인 사람에게 아침 메시지, 저녁 시간이 그 칸인 사람에게 저녁 메시지를 보낸다. 하루 한 번 보장(`sent_messages`)은 그대로라 시간을 바꿔도 같은 날 두 번 가지 않는다. 발송 기록(`send_runs`)은 지금처럼 종류별로 더한다.
- 서버 crontab: `30 7 * * *`·`0 21 * * *` 두 줄 → `0,30 * * * *` 한 줄. 저장소 밖이라 배포 때 서버에서 직접 바꾸고 runbook에 기록.
- 화면: 기록 화면 맨 위 카톡 바의 '설정'을 펼치면 아침·저녁 `<select>` 두 개와 [저장] 버튼. 새 경로 `POST /c/{token}/kakao/times`(목록 밖 값은 400, 요청 제한은 기존 끄기·켜기와 같은 것). JS 없이 동작.
- 문구: 카톡 바 "💬 카카오톡 연결됨 · 아침 7:30 / 저녁 9시"와 연결 환영 메시지는 그 사람이 고른 시간으로. 연결 전 안내(`_macros.html`)는 "기본 아침 7:30·저녁 9시, 연결 후 바꿀 수 있어요". 랜딩 데모의 "오전 7:30"은 예시라 그대로.
- 문서: requirements(FR 추가·수정), api(새 경로·cron), erd(두 칸), wireframes(카톡 바), runbook(ALTER·crontab), 발표 슬라이드(다음 단계·매일 이어지게 장).

## 빌더에게 맡김
- 시각 표기 함수(예: 21:00 → "저녁 9시", 07:30 → "아침 7:30")의 세부 형식.
- 테스트 구성. 단, 칸 경계(07:30 정각, 07:59 → 07:30 칸), 시간 바꾼 날 중복 없음, 목록 밖 값 거부는 꼭 확인.
