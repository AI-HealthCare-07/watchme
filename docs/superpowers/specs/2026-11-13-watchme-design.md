# Watchme 설계 문서 (v0.2, 승인됨 · 2026-11-13 Opus 검토 반영)

## 1. 의도와 이유
- 고혈압·당뇨 생활습관 챌린지 웹 서비스. **포트폴리오 프로젝트**.
- 흐름: 무료 1달 체험 → 변화 리포트 → 유료(카카오톡) 전환 유도.
- 사용자가 직접 정한 핵심 학습 목표 2가지: **① 집 서버 구축, ② 카카오톡 연동.** 기능 완성도보다 이 둘을 실제로 경험하는 것이 우선한다.

## 2. 목표 / 비목표 / 안티목표
**목표**
- 성별·나이·키·몸무게 입력 → 한국 평균과 비교한 참고 위험도 → 1달 식단+가벼운 운동 계획 PDF.
- PDF에 **1년 시나리오**: 계획을 지켰을 때 3·6·12개월 뒤 체중과 그때의 참고 위험도 표 ("예측"이 아닌 "시나리오" 표기). 가정: BMI 23 이상은 12개월간 체중 6% 감량(선형), 23 미만은 유지.
- 폰에서 매일 체크(지켰는지, 체중)를 기록하는 모바일 웹 페이지.
- 1달 뒤 변화 리포트(체중 변화, 평균 대비 위험도 변화) + 유료 전환 안내.
- 집 서버(노트북)에서 실제로 서비스 운영.
- 2단계: 카카오 로그인, 아침 푸시, 저녁 체크·일요일 체중 입력.

**비목표**
- 실제 의료 진단·예측 (표현은 "참고 위험도", 면책 문구 필수).
- 별도 네이티브 앱.
- 실결제 구현 (유료 전환은 안내/가입까지만, 결제 연동은 범위 밖).
- 필수 PDF 업로드 파싱 (선택 기능, 후순위).
- 알림톡/친구톡(사업자·대행사·건당 과금 필요).

**안티목표**
- 의학적 확정처럼 보이는 문구.
- 공개 인터넷에 개인 건강 데이터를 허술하게 노출 (보안·백업을 같이 다룬다).
- 집 서버가 막혔다고 프로젝트 전체가 멈추는 구조.

## 3. 제약
- 서버: 사용자 보유 노트북 1대, 가정용 KT 인터넷 (80/443 인바운드 차단·공인 IP 문제 가능성 → 확인 필요).
- 도메인: `evrd.fyi` 사용, 서브도메인 없이 루트 도메인 그대로 사용 (watchme는 부제일 뿐).
- 카카오 개발자 계정과 앱 등록은 사용자가 직접 한다.
- 입력 환경은 주로 **폰**. 모바일 우선.
- 개인 건강정보를 다루므로 최소 수집, 접근은 비추측 토큰 기반. 시작 폼에 수집 항목·보관 기간 안내.
- 공개 서버이므로 요청 제한 필수(체험 생성·기록 저장).
- 모든 날짜는 `Asia/Seoul` 기준. 공개 주소는 `PUBLIC_BASE_URL` 환경변수로 명시(프록시 뒤에서 요청 주소를 믿지 않음).
- 체험 시작 시 고른 계획 종류를 저장해 체험 중 템플릿이 바뀌어도 사용자의 계획은 고정.

## 4. 접근 방식 (검토한 안과 선택)
**(가) 카카오 연동**
- A 카카오 로그인 + "나에게 보내기" (무료, 대화 불가) / B 채널+챗봇(양방향) / C 알림톡(과함).
- **선택: A로 시작, B는 나중에 추가.** 저녁 체크는 B 전까지 푸시 메시지의 버튼에서 웹 체크 페이지로 연결해 대체 가능.

**(나) 입력 수단**
- 폰에서는 입력 가능한 PDF 양식이 불안정 → PDF는 읽기·보관·인쇄용, 실제 기록은 모바일 웹 체크 페이지. PDF 업로드 분석은 선택 기능.

**(다) 사용자 식별**
- 선택: **(2) 로그인 없이 비추측 개인 링크(`/c/<랜덤토큰>`)로 시작**, 유료 전환 시 카카오 로그인으로 기록을 계정에 연결. 이유: 1단계를 MVP로 분리하고 진입 장벽을 낮춤. 약점: 링크 분실 시 기록 분실.

**(라) 단계 분리**
- 선택: 1단계(무료 체험 전체, DB 포함) → 2단계(유료, 카카오). 기록·리포트는 1단계에 포함.

**(마) 집 서버 공개 방식**
- 1 포트포워딩+DDNS+Nginx+Let's Encrypt (배움 큼, KT 포트 차단 시 불가) / 2 Cloudflare Tunnel (안전, 도메인 필요) / 3 하이브리드.
- **선택(갱신): 3의 변형.** ① Tailscale Funnel(`*.ts.net`, 도메인 작업 없음)로 먼저 서비스 공개 → ② Porkbun DNS 그대로 `evrd.fyi`에 포트포워딩+DDNS(Porkbun API)+HTTPS를 학습 과제로 시도 → ③ KT 포트 차단으로 막히면 Cloudflare로 이전 후 Tunnel(선택).
- 근거: evrd.fyi는 사용자가 폐기 예정인 EVRDay(Vercel)의 도메인이며 네임서버는 Porkbun. Cloudflare Tunnel만 Cloudflare DNS를 요구하므로 처음부터 이전할 필요 없음.
- SSH/관리 접속은 Tailscale 내부망으로만 허용하고 인터넷에는 웹(443)만 노출.

## 5. 결정 사항 (사용자가 정한 것 vs 제 판단)
**사용자 결정**: 포트폴리오 목적, 카카오 연동 시도, 단계 분리, 개인 링크 방식, 기록·리포트는 1단계 포함, 하이브리드 공개 방식, 노트북+evrd.fyi+KT.

**제 판단 (바꿀 수 있음)**
- 백엔드 Python(FastAPI), 서버 렌더링 HTML + 가벼운 JS, PostgreSQL, Docker Compose.
- PDF는 reportlab + NanumGothic (윈도우 개발 PC에서 설치 쉬움).
- 서버 OS는 Ubuntu Server (노트북 덮개 닫아도 동작하도록 설정 포함).
- "참고 위험도" = sigmoid(b0 + b1·BMI) ÷ (같은 성별·연령대 전체 유병률). b0, b1은 국민건강영양조사 2022–2024 원시자료로 성별×연령대×질환마다 가중 로지스틱 회귀(연속 BMI 모델, v0.3 — 구간 방식은 구간 경계를 넘지 않으면 30일 변화가 0으로 보여 변경). BMI 16–40 밖은 경계값으로 계산. 면책 문구 필수.
- 배포: 비공개 GitHub 저장소 → 서버에서 `git pull && docker compose up -d --build`.
- 백업: 매일 `pg_dump`, 서버 밖(다른 기기)으로 복사.
- 데모: 30일치 기록이 채워진 데모 체험 생성 스크립트.

## 6. 1단계 범위 (구현 순서 제안)
**서버 먼저**: 배포 환경 문제(프록시 주소, 시간대)를 일찍 발견하고 핵심 학습 목표를 앞당김.
1. 앱 골격 + Docker Compose.
2. 집 서버 구축(Ubuntu Server, SSH 키·방화벽, Tailscale, Docker, 백업) 후 골격을 Funnel로 공개.
3. 기능을 하나씩 만들고 끝날 때마다 배포: 위험도 → 계획 → PDF → 기록 → 체크 화면 → 리포트.
4. (과제) evrd.fyi 포트포워딩 + DDNS + HTTPS.

## 7. 2단계 범위 (개요)
카카오 로그인(개인 링크 기록 연결), "나에게 보내기" 아침 푸시, 웹 체크로 저녁 응답, 일요일 체중 입력 요청, 이후 챗봇(B)으로 맞춤 응답.

## 8. 빌더에게 남긴 것
- 한국 평균 키·체중, 연령별 고혈압·당뇨 유병률의 공개 통계 출처 선정 (국민건강영양조사, 건강보험공단 등).
- 참고 위험도 계산식과 면책 문구.
- 식단·운동 계획 생성 방식 (고정 템플릿 우선, 개인화는 단순 규칙).
- DB 스키마, 토큰 길이·보관 방식, 백업 주기.
- 체험 기간 정의 (시작일 기준 30일, 중간에 빠진 날 처리).

## 9. 열린 항목
- (해결) 노트북은 초기화하고 Ubuntu Server 설치 가능. 같은 노트북을 24시간 AI 에이전트용으로도 사용 예정(Tailscale) → 컨테이너로 분리하고 Watchme DB에는 접근 불가하게 구성. (부가 과제, 서버 구축 단계에서 다룸)
- (해결) evrd.fyi: EVRDay는 폐기 예정, DNS는 Porkbun 유지.
- KT 회선의 공인 IP 여부와 80/443 차단 여부 (포트포워딩 과제 시점에 확인).
- 노트북 사양(RAM/저장장치)과 덮개 닫힘·전원 설정 확인.
