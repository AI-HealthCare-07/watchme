# 요구사항 정의서

- 서비스: **Watchme** — 한국인 평균과 비교한 고혈압·당뇨 참고 위험도 + 30일 생활습관 챌린지
- 근거 문서: `docs/superpowers/specs/2026-11-13-watchme-design.md`(원래 설계), `2026-11-16-watchme-redesign-design.md`(1단계 개편), `2026-11-16-watchme-phase2-design.md`(2단계), `2026-11-18-watchme-phase3-ai-design.md`(3단계), `2026-11-18-watchme-weekly-report-design.md`(주간 리포트), `2026-11-18-watchme-admin-metrics-design.md`(운영 지표)
- 상태 표기: ✅ 구현·배포 완료 · ⛔ 범위 밖

## 1. 개요

| 항목 | 내용 |
|---|---|
| 목적 | 성별·나이·키·몸무게만으로 같은 성별·나이대 평균 대비 위험도를 보여 주고, 30일 맞춤 계획과 매일 체크로 습관을 만든다 |
| 차별점 | 체중이 아니라 **"한국인 평균 대비 내 병 위험"이 매주 내려가는 게 보인다** (국민건강영양조사 2022–2024 원시자료로 만든 모델) |
| 대상 | 폰으로 쓰는 성인(18~100세). 로그인 없이 개인 링크로 시작 |
| 학습 목표 | ① 집 서버 직접 구축·운영 ② 카카오톡 연동 끝까지 경험 ③ 무료 LLM API를 최소한으로 붙여 보기 |
| 배포 | https://evrd.fyi (집 노트북 Ubuntu Server, Docker Compose, Caddy HTTPS) |

## 2. 기능 요구사항

### 2.1 1단계 — 무료 30일 체험 (✅)

| ID | 요구사항 | 상세 | 상태 |
|---|---|---|---|
| FR-01 | 시작 화면 | 스토리형 5장면(소개 → 예시 45세 남성 실제 위험도 → 30일 달력 → 실제와 같은 카톡 메시지 → 시작 권유), 자동 전환·진행 막대 눌러 이동·화면 눌러 다음, 개인정보 안내(접힘). JS 없으면 세로로 쌓임. 통계 파일이 없으면 "준비 중" (2026-11-18 개편) | ✅ |
| FR-01a | 대표 아이콘 | 맥박 W 아이콘: 브라우저 탭, 홈 화면 추가(manifest), 카톡 링크 미리보기(og 태그·1200×630 그림), 모든 화면 머리 | ✅ |
| FR-02 | 몸 정보 입력 | 성별 → 출생연도 → 키 → 몸무게, 한 화면 한 질문(토스식). 출생연도로 받아 나이(올해 − 출생연도)로 바꿔 씀(사용자 피드백 반영). 범위: 나이 18–100(출생연도 올해−100 ~ 올해−18), 키 120–220, 몸무게 30–250. JS가 꺼져도 일반 폼으로 동작 | ✅ |
| FR-03 | 참고 위험도 계산 | 성별×연령대×질환별 가중 로지스틱 회귀(연속 BMI, 16–40 밖은 경계값) ÷ 같은 성별·연령대 유병률 → "평균보다 N% 높음/낮음", 수준(낮음/보통/높음) | ✅ |
| FR-04 | 결과 화면 | 수준별 요약 문장, 고혈압·당뇨 막대(가운데 선 = 평균), BMI 23 이상이면 3개월 시나리오 한 줄 | ✅ |
| FR-05 | 맞춤 질문 5개 | 식사 스타일 / 점심 장소 / 아침 습관 / 운동 가능 시간 / 자유 한 끼 요일(정확히 2개) | ✅ |
| FR-06 | 계획 종류 결정 | 위험도로 normal(유지·습관) / overweight(가벼운 감량) / obese(무릎 보호) / high_risk(안전 우선 저강도). 시작 시 고정 | ✅ |
| FR-07 | 30일 맞춤 계획 | 규칙 기반 조합(메뉴·운동·팁 JSON 풀). 토큰 시드로 항상 같은 계획, 연속 중복 최소화, 끼니 거르기 없음 | ✅ |
| FR-08 | 준비 완료 화면 | 응원 + 주의사항 4개(진단 아님, 치료 중이면 의료진 우선, 운동 중 이상 증상 시 중단, 급감량 금지) → 6초 뒤 Day 1(카톡 연결 카드가 보이면 자동 이동 안 함) | ✅ |
| FR-09 | 매일 기록 | 오늘 계획 카드(아이콘 + 메뉴, 팁 한 줄), 체중(선택), 지켰어요/못 지켰어요. 10초 안에 끝. 지난 날은 도장판에서 눌러 수정 — 그때 제목이 그날로 바뀌고 주황 띠 "지난 기록을 고치는 중이에요" + "오늘로 돌아가기", 저장 후 그날 화면에 머묾 | ✅ |
| FR-10 | 연속 기록·계획 칩 | 제목 밑 칩: 계획 이름(예: 무릎 보호 감량), "💪 강도 N단계", "🔥 N일 연속". 혼내는 문구 없음 | ✅ |
| FR-11 | 하루 팁(계획 카드 안 한 줄) | 30일 중복 없음, 답변 맞춤(편의점·아침 거름·외식), 자유 한 끼 날 전용 팁 | ✅ |
| FR-12 | 의심 카드 | 최근 7일 중 6일 이상 지킴 + 체중 2회 이상 기록 + 마지막 ≥ 처음 → 숨은 원인 하나(음료·간식·소스·양 순환) + 안심 문구 | ✅ |
| FR-13 | 주간 요약 | 7·14·21·28일째 기록 후 ~ 다음 날까지. 지킨 날, 체중 변화, 위험도 변화 | ✅ |
| FR-14 | 강도 올리기 | 정체 조건이면 "올리기 / 이대로 유지" 질문. 주당 1회, 최대 2단계, 다음 주 첫날부터 적용. high_risk는 운동만 증가 | ✅ |
| FR-15 | 주간 계획표 PDF | 1~4주 7일, 5주 2일. 표(끼니·운동·○×·체중 칸) + 팁 + QR + 면책. 1주차엔 "내 결과 요약"(1년 시나리오) 한 장 추가. 다음 주는 그 주 마지막 날부터 | ✅ |
| FR-16 | 30일 리포트 | 31일째부터. 체중 변화, 평균 대비 위험도 처음 → 지금, 기록 부족 안내(체중 2회·10일 미만) | ✅ |
| FR-17 | 안내·오류 화면 | 404(체험 없음), 400(잘못된 입력·아직 못 하는 날), 429(요청 과다), 503(통계 준비 중)을 같은 디자인으로 | ✅ |

### 2.2 2단계 — 카카오 로그인 + 하루 두 번 카톡 (✅ 2026-11-17 운영 확인)

| ID | 요구사항 | 상세 | 상태 |
|---|---|---|---|
| FR-21 | 카카오로 연결 | /ready 노란 카드·기록 화면 맨 위 노란 바 → 카카오 로그인·동의(`talk_message`만) → 체험을 계정에 연결. 1일째부터 가능 | ✅ |
| FR-22 | 카카오로 이어서 하기 | 시작 화면 시작 버튼 밑 작은 글씨 링크(2026-11-18 개편 전엔 노란 버튼) → 계정의 가장 최근 체험으로 이동(다른 기기에서 링크 복구) | ✅ |
| FR-23 | 환영 메시지 | 연결 직후 "나에게 보내기" 1통(하루 한 번). 폰 알림이 울리지 않으니 '나와의 채팅'을 직접 열어 확인하라는 안내 포함 | ✅ |
| FR-24 | 아침 7:30 메시지 | Day n 오늘 계획(아침·점심·저녁·운동), 일요일은 체중 재는 날 안내 | ✅ |
| FR-25 | 저녁 21:00 메시지 | 기록 없으면 "10초면 기록돼요", 있으면 "기록 고마워요". 7·14·21·28일째는 주간 요약 안내 추가 | ✅ |
| FR-26 | 31일째 리포트 메시지 | "30일 완주! 리포트가 나왔어요" 후 그 체험은 발송 멈춤 | ✅ |
| FR-27 | 메시지 끄기·켜기 / 연결 끊기 | 기록 화면 맨 위 노란 바 "💬 카카오톡 연결됨 · 아침 7:30 / 저녁 9시" → 설정. 끄기는 `notify=false`만. 끊기는 카카오 unlink + 저장 토큰 즉시 삭제 | ✅ |
| FR-28 | 다음 30일 도전 | 리포트에서 버튼 → 마지막 체중·같은 답변으로 새 체험, 같은 계정에 연결. 한 체험에서 한 번만 | ✅ |
| FR-29 | 키 없을 때 | 카카오 키가 없는 환경에선 카카오 버튼·카드 숨김, 카카오 경로 404, 1단계 그대로 동작 | ✅ |

### 2.3 3단계 — AI 한 줄 요청 (✅ 구현, 2026-11-18 운영 반영)

| ID | 요구사항 | 상세 | 상태 |
|---|---|---|---|
| FR-31 | 한 줄 요청 | 설정 6번째 단계(선택): "식단·운동에서 빼고 싶은 게 있나요?" 100자. 비우면 AI 호출 없음. 키 없으면 단계 숨김 | ✅ |

| FR-33 | 안전장치 | 목록 밖 번호·JSON 이상·종류별 절반 넘게 빼기·실패·8초 초과(전체 대기 시간 기준) → AI 결과 버리고 기본 계획. 요청 글이 프롬프트 칸을 닫지 못하게 `<`·`>` 바꿔 보냄 | ✅ |
| FR-34 | 보여 주기 | 준비 화면 "🤖 이 계획은 AI가 내 요청에 맞춰 골라 줬어요"(뺀 항목은 안 보여 줌), 기록 화면 칩 "🤖 AI 맞춤". 다음 30일 도전에 그대로 복사 | ✅ |

| FR-40 | 주간 카톡 | 8·15·22·29일째 아침 7:30엔 계획 대신 지난주 리포트 메시지 + [리포트 보기] | ✅ |

### 2.5 운영 지표 (✅ 구현, 2026-11-18 운영 반영)

| ID | 기능 | 설명 | 상태 |
|---|---|---|---|
| FR-41 | 관리 화면 | 나만 여는 `/admin`. 서버 `.env`의 `ADMIN_KEY`가 비면 기능 꺼짐(404). `?key=`가 맞으면 키 해시 쿠키(HttpOnly, 180일) 후 `/admin`으로 이동, 틀리면 404·10번 넘으면 429. `noindex`·`no-store` | ✅ |
| FR-42 | 카톡 연결자 | 맨 위 큰 숫자 = 지금 알림 받는 사람(동의·알림 켬·토큰 있음). 옆에 연결·끊김·알림 끔·오늘 새 연결 | ✅ |
| FR-43 | 추이·전환·지속률 | 최근 30일 날짜별(조회·시작·질문 완료·새 연결·체크), 단계별 전환(랜딩 조회→시작→질문 완료→카톡 연결, %), 1·7·14·30일째 체크 지속률, 다음 도전 수, AI 요청 결과, 카톡 발송 보냄·실패(최근 7일) | ✅ |
| FR-44 | 랜딩 조회 카운터·테스트 제외 | 랜딩을 열 때 KST 날짜별 +1(봇·링크 미리보기 제외, IP·쿠키·브라우저 정보 저장 안 함). 관리자 브라우저로 시작한 체험(과 그 다음 도전)·`METRICS_SINCE` 이전 체험·계정은 모든 숫자에서 뺌 | ✅ |

### 2.6 범위 밖 (⛔)

실결제·효도 구독(사업자 정리 전까지 무료 서비스 유지), 주간 "AI 코치 한마디"(나중에 할 일), AI가 계획 통째 생성, 친구에게 보내기·채널 챗봇·알림톡, 알림 시간 선택, 31일 이후 계획 연장, 리더보드, 네이티브 앱, 의학적 진단.

## 3. 비기능 요구사항

| ID | 분류 | 요구사항 | 상태 |
|---|---|---|---|
| NFR-01 | 개인정보 | 이름·연락처·이메일 수집 없음. 수집 항목·보관 기간을 시작 화면에 안내. 체험 종료 후 90일 뒤 자동 삭제. 한 줄 요청을 적으면 AI(구글 Gemini)로 보내고 체험과 함께 삭제한다고 안내(3단계). | ✅ |
| NFR-02 | 접근 제어 | 추측 불가 토큰 링크(`/c/{token}`). `noindex`, `no-referrer` | ✅ |
| NFR-03 | 남용 방지 | IP별 요청 제한: 체험 생성 10분 5회 + 전체 하루 500회, 기록·강도 저장 1분 30회 | ✅ |
| NFR-04 | 의료 표현 | "참고 위험도", "시나리오"(예측 아님), 모든 화면·PDF에 면책 문구, 효과 장담 금지 | ✅ |
| NFR-05 | 모바일 우선 | 폭 최대 480px, 숫자 키패드, 저가형 폰에서도 가볍게. 라이트 모드 고정(`color-scheme: only light`, 2026-11-18 사용자 요청), `prefers-reduced-motion` 대응 | ✅ |
| NFR-06 | 점진적 향상 | JS 없이도 시작·입력·기록 동작. 외부 스크립트·CDN·추적기 0개(글꼴 자체 호스팅) | ✅ |
| NFR-07 | 시간대 | 모든 날짜 KST(`today_kst`). 공개 주소는 `PUBLIC_BASE_URL`(프록시 헤더를 믿지 않음) | ✅ |
| NFR-08 | 운영 | 집 서버, Docker Compose(app·db·caddy), `git push`로 배포, 매일 `pg_dump` 백업 + 서버 밖 사본, DDNS | ✅ |
| NFR-09 | 보안(서버) | SSH는 Tailscale 내부망만, 인터넷엔 80/443만. 앱 포트는 127.0.0.1에만 바인딩 | ✅ |
| NFR-10 | 테스트 | pytest 349개(TDD), 카카오는 실제 호출 없이 MockTransport | ✅ |
| NFR-11 | 토큰 보관 | 카카오 리프레시 토큰은 Fernet 암호화(키는 서버 `.env`만) → 백업만으론 못 풂 | ✅ |
| NFR-12 | 발송 신뢰성 | 같은 (계정, 날짜, 종류)는 최대 한 번. 실패해도 재시도 없음(두 번 가는 것보다 한 번 빠지는 게 낫다) | ✅ |
| NFR-13 | OAuth 보안 | `state`는 요청마다 랜덤, 체험 토큰은 서명한 HttpOnly 쿠키에만(카카오 URL에 안 넣음) | ✅ |
| NFR-14 | AI로 보내는 정보 | 한 줄 요청과 후보 메뉴·운동 목록만. 성별·나이·키·체중·위험도·토큰은 안 보냄. 요청 문장은 로그에 안 남김 | ✅ |

## 4. 성공 기준

| 단계 | 기준 |
|---|---|
| 1단계 | 처음 온 사람이 시작 → 기록 화면까지 2분 안 / 매일 체크 10초 안 / 30일 메뉴 반복이 눈에 안 띔 / JS 꺼도 동작 |
| 3단계 | "매운 거 못 먹어요" → 30일 계획에서 매운 메뉴가 빠지고 이유 한 줄 / 키 없으면 1·2단계 그대로 / AI가 엉뚱하게 답해도 기본 계획 |
| 2단계 | 내 폰에서 연결 → 다음 날 아침·저녁 메시지 → 버튼으로 기록 / 다른 기기에서 같은 체험 복구 / cron 두 번 실행해도 한 통 / 연결 끊기 후 DB에 토큰 없음 |
