# 요구사항 정의서

- 서비스: **Watchme** — 한국인 평균과 비교한 고혈압·당뇨 참고 위험도 + 30일 생활습관 챌린지
- 근거 문서: `docs/superpowers/specs/2026-11-13-watchme-design.md`(원래 설계), `2026-11-16-watchme-redesign-design.md`(1단계 개편), `2026-11-16-watchme-phase2-design.md`(2단계)
- 상태 표기: ✅ 구현·배포 완료 · 🔜 2단계 예정(설계·계획 완료, 구현 전) · ⛔ 범위 밖

## 1. 개요

| 항목 | 내용 |
|---|---|
| 목적 | 성별·나이·키·몸무게만으로 같은 성별·나이대 평균 대비 위험도를 보여 주고, 30일 맞춤 계획과 매일 체크로 습관을 만든다 |
| 차별점 | 체중이 아니라 **"한국인 평균 대비 내 병 위험"이 매주 내려가는 게 보인다** (국민건강영양조사 2022–2024 원시자료로 만든 모델) |
| 대상 | 폰으로 쓰는 성인(18~100세). 로그인 없이 개인 링크로 시작 |
| 학습 목표 | ① 집 서버 직접 구축·운영 ② 카카오톡 연동 끝까지 경험 |
| 배포 | https://evrd.fyi (집 노트북 Ubuntu Server, Docker Compose, Caddy HTTPS) |

## 2. 기능 요구사항

### 2.1 1단계 — 무료 30일 체험 (✅)

| ID | 요구사항 | 상세 | 상태 |
|---|---|---|---|
| FR-01 | 시작 화면 | 예시 인물(45세 남성 172cm 82kg)의 실제 계산 결과, 특징 3개, 개인정보 안내. 통계 파일이 없으면 "준비 중" | ✅ |
| FR-02 | 몸 정보 입력 | 성별 → 나이 → 키 → 몸무게, 한 화면 한 질문(토스식). 범위: 나이 18–100, 키 120–220, 몸무게 30–250. JS가 꺼져도 일반 폼으로 동작 | ✅ |
| FR-03 | 참고 위험도 계산 | 성별×연령대×질환별 가중 로지스틱 회귀(연속 BMI, 16–40 밖은 경계값) ÷ 같은 성별·연령대 유병률 → "평균보다 N% 높음/낮음", 수준(낮음/보통/높음) | ✅ |
| FR-04 | 결과 화면 | 수준별 요약 문장, 고혈압·당뇨 막대(가운데 선 = 평균), BMI 23 이상이면 3개월 시나리오 한 줄 | ✅ |
| FR-05 | 맞춤 질문 5개 | 식사 스타일 / 점심 장소 / 아침 습관 / 운동 가능 시간 / 자유 한 끼 요일(정확히 2개) | ✅ |
| FR-06 | 계획 종류 결정 | 위험도로 normal(유지·습관) / overweight(가벼운 감량) / obese(무릎 보호) / high_risk(안전 우선 저강도). 시작 시 고정 | ✅ |
| FR-07 | 30일 맞춤 계획 | 규칙 기반 조합(메뉴·운동·팁 JSON 풀). 토큰 시드로 항상 같은 계획, 연속 중복 최소화, 끼니 거르기 없음 | ✅ |
| FR-08 | 준비 완료 화면 | 응원 + 주의사항 4개(진단 아님, 치료 중이면 의료진 우선, 운동 중 이상 증상 시 중단, 급감량 금지) → 6초 뒤 Day 1 | ✅ |
| FR-09 | 매일 기록 | 오늘 계획 카드, 체중(선택), 지켰어요/못 지켰어요. 10초 안에 끝. 지난 날은 도장판에서 눌러 수정 | ✅ |
| FR-10 | 연속 기록·격려 | "N일 연속 지키는 중 🔥", 첫날·끊긴 날은 다른 격려 문구. 혼내지 않기 | ✅ |
| FR-11 | 하루 팁 | 30일 중복 없음, 답변 맞춤(편의점·아침 거름·외식), 자유 한 끼 날 전용 팁 | ✅ |
| FR-12 | 의심 카드 | 최근 7일 중 6일 이상 지킴 + 체중 2회 이상 기록 + 마지막 ≥ 처음 → 숨은 원인 하나(음료·간식·소스·양 순환) + 안심 문구 | ✅ |
| FR-13 | 주간 요약 | 7·14·21·28일째 기록 후 ~ 다음 날까지. 지킨 날, 체중 변화, 위험도 변화 | ✅ |
| FR-14 | 강도 올리기 | 정체 조건이면 "올리기 / 이대로 유지" 질문. 주당 1회, 최대 2단계, 다음 주 첫날부터 적용. high_risk는 운동만 증가 | ✅ |
| FR-15 | 주간 계획표 PDF | 1~4주 7일, 5주 2일. 표(끼니·운동·○×·체중 칸) + 팁 + QR + 면책. 1주차엔 "내 결과 요약"(1년 시나리오) 한 장 추가. 다음 주는 그 주 마지막 날부터 | ✅ |
| FR-16 | 30일 리포트 | 31일째부터. 체중 변화, 평균 대비 위험도 처음 → 지금, 기록 부족 안내(체중 2회·10일 미만) | ✅ |
| FR-17 | 안내·오류 화면 | 404(체험 없음), 400(잘못된 입력·아직 못 하는 날), 429(요청 과다), 503(통계 준비 중)을 같은 디자인으로 | ✅ |

### 2.2 2단계 — 카카오 로그인 + 하루 두 번 카톡 (🔜)

| ID | 요구사항 | 상세 | 상태 |
|---|---|---|---|
| FR-21 | 카카오로 연결 | /ready·기록 화면의 노란 카드 → 카카오 로그인·동의(`talk_message`만) → 체험을 계정에 연결. 1일째부터 가능 | 🔜 |
| FR-22 | 카카오로 이어서 하기 | 시작 화면 보조 링크 → 계정의 가장 최근 체험으로 이동(다른 기기에서 링크 복구) | 🔜 |
| FR-23 | 환영 메시지 | 연결 직후 "나에게 보내기" 1통 | 🔜 |
| FR-24 | 아침 7:30 메시지 | Day n 오늘 계획(아침·점심·저녁·운동), 일요일은 체중 재는 날 안내 | 🔜 |
| FR-25 | 저녁 21:00 메시지 | 기록 없으면 "10초면 기록돼요", 있으면 "기록 고마워요". 7·14·21·28일째는 주간 요약 안내 추가 | 🔜 |
| FR-26 | 31일째 리포트 메시지 | "30일 완주! 리포트가 나왔어요" 후 그 체험은 발송 멈춤 | 🔜 |
| FR-27 | 알림 끄기·켜기 / 연결 끊기 | 끄기는 `notify=false`만. 끊기는 카카오 unlink + 저장 토큰 즉시 삭제 | 🔜 |
| FR-28 | 다음 30일 도전 | 리포트에서 버튼 → 마지막 체중·같은 답변으로 새 체험, 같은 계정에 연결. 한 체험에서 한 번만 | 🔜 |
| FR-29 | 키 없을 때 | 카카오 키가 없는 환경에선 카카오 버튼·카드 숨김, 카카오 경로 404, 1단계 그대로 동작 | 🔜 |

### 2.3 범위 밖 (⛔, 3단계 후보)

실결제, 효도 구독(자녀가 부모 소식 받기), 친구에게 보내기·채널 챗봇·알림톡, 알림 시간 선택, 31일 이후 계획 연장, 리더보드, 네이티브 앱, AI 생성 계획, 의학적 진단.

## 3. 비기능 요구사항

| ID | 분류 | 요구사항 | 상태 |
|---|---|---|---|
| NFR-01 | 개인정보 | 이름·연락처·이메일 수집 없음. 수집 항목·보관 기간을 시작 화면에 안내. 체험 종료 후 90일 뒤 자동 삭제 | ✅ |
| NFR-02 | 접근 제어 | 추측 불가 토큰 링크(`/c/{token}`). `noindex`, `no-referrer` | ✅ |
| NFR-03 | 남용 방지 | IP별 요청 제한: 체험 생성 10분 5회 + 전체 하루 500회, 기록·강도 저장 1분 30회 | ✅ |
| NFR-04 | 의료 표현 | "참고 위험도", "시나리오"(예측 아님), 모든 화면·PDF에 면책 문구, 효과 장담 금지 | ✅ |
| NFR-05 | 모바일 우선 | 폭 최대 480px, 숫자 키패드, 저가형 폰에서도 가볍게. 다크 모드, `prefers-reduced-motion` 대응 | ✅ |
| NFR-06 | 점진적 향상 | JS 없이도 시작·입력·기록 동작. 외부 스크립트·CDN·추적기 0개(글꼴 자체 호스팅) | ✅ |
| NFR-07 | 시간대 | 모든 날짜 KST(`today_kst`). 공개 주소는 `PUBLIC_BASE_URL`(프록시 헤더를 믿지 않음) | ✅ |
| NFR-08 | 운영 | 집 서버, Docker Compose(app·db·caddy), `git push`로 배포, 매일 `pg_dump` 백업 + 서버 밖 사본, DDNS | ✅ |
| NFR-09 | 보안(서버) | SSH는 Tailscale 내부망만, 인터넷엔 80/443만. 앱 포트는 127.0.0.1에만 바인딩 | ✅ |
| NFR-10 | 테스트 | pytest 152개(TDD), 카카오는 실제 호출 없이 MockTransport | ✅ / 🔜 |
| NFR-11 | 토큰 보관 | 카카오 리프레시 토큰은 Fernet 암호화(키는 서버 `.env`만) → 백업만으론 못 풂 | 🔜 |
| NFR-12 | 발송 신뢰성 | 같은 (계정, 날짜, 종류)는 최대 한 번. 실패해도 재시도 없음(두 번 가는 것보다 한 번 빠지는 게 낫다) | 🔜 |
| NFR-13 | OAuth 보안 | `state`는 요청마다 랜덤, 체험 토큰은 서명한 HttpOnly 쿠키에만(카카오 URL에 안 넣음) | 🔜 |

## 4. 성공 기준

| 단계 | 기준 |
|---|---|
| 1단계 | 처음 온 사람이 시작 → 기록 화면까지 2분 안 / 매일 체크 10초 안 / 30일 메뉴 반복이 눈에 안 띔 / JS 꺼도 동작 |
| 2단계 | 내 폰에서 연결 → 다음 날 아침·저녁 메시지 → 버튼으로 기록 / 다른 기기에서 같은 체험 복구 / cron 두 번 실행해도 한 통 / 연결 끊기 후 DB에 토큰 없음 |
